\title{Beyond the Issue: How Often Coding-Agent Pull Requests\\Change What Nobody Asked For}
\author{\IEEEauthorblockN{Harshul Jain}\IEEEauthorblockA{Independent Researcher}}
\maketitle

\begin{abstract}\normalfont
Reviewers of pull requests (PRs) opened by coding agents often compare the linked issue with the changed files by hand, looking for ``helpful'' extras nobody asked for. We measure how often such extras occur, using \nCorpus{} agent PRs from the public AIDev dataset whose linked issue text and per-file patches are available. We use Fence, a deterministic checker that flags every changed file or formatting-only hunk that nothing in the issue points to. By Fence's flags, \pctReach\% of PRs it could anchor to the issue change at least one such part, and on average \meanReach\% of a PR's changed lines are outside the issue. Flag rates differ widely by agent (from \reachJules\% to \reachCopilot\%), but most of the gap follows PR size: re-weighted to the same file-count mix, Copilot drops from \reachCopilot\% to \stdCopilot\%. We also report a negative result. On \nPai{} human scope-creep labels from PAIChecker, plain PR size ranks scope creep better than Fence (AUROC \aucSize{} vs \aucFence), and adding Fence to size does not help. Fence's precision is not yet measured: a \goldPRs-PR gold sheet is ready for human labels. All rates here are therefore tool output, not verified prevalence.
\end{abstract}

\section{Introduction}
Coding agents now open hundreds of thousands of PRs on GitHub~\cite{li2026aidev}. A common complaint is that they do more than they were asked: they reformat files, bump dependencies, edit CI or rewrite code the issue never mentioned. Such extras matter. In a study of 33{,}580 agent PRs, unintended side effects (22.33\%) and overengineering (22.13\%) were more common causes of later reverts than functional bugs (17.71\%)~\cite{oukhay2026revert}. Tangled changes are known to cost reviewers and to bias mining studies~\cite{herzig2013tangled}.

Prior work compared the PR \emph{description} with the code~\cite{gong2026prmci}, or used LLMs to judge whether a PR matches its issue on small sets of human PRs~\cite{isik2025forge,altunhan2026finetune} and on SWE-bench-style benchmarks~\cite{wang2026paichecker}. Agent out-of-scope actions were also measured in sandboxes~\cite{qu2026overeager,trong2026swemisbehavior}. What is missing is a measurement of issue-versus-diff scope on real agent PRs at scale, broken down by the part of the diff that goes beyond the issue.

We provide that measurement, with an explicit caveat: our instrument is a rule-based checker whose precision is not yet measured. Our contributions are: (1) scope-reach rates on \nCorpus{} agent PRs from \nRepos{} repositories, by agent, task type and kind of extra; (2) evidence that PR size explains most of the difference between agents and between merged and unmerged PRs; and (3) a check against independent human labels, where PR size beats Fence.

\section{Method}
\textbf{Data.} AIDev v5~\cite{li2026aidev} (CC BY 4.0) lists agent PRs with their linked issues and per-commit file patches. We keep PRs whose linked issue has usable text and whose changed files carry patches for at least 90\% of file rows: \nCorpus{} PRs. Task types come from AIDev-full's labels and cover \nTyped{} of them.

\textbf{Instrument.} Fence~\cite{fencetool} extracts from the issue the paths, code names (\texttt{camelCase}, \texttt{snake\_case}, dotted names) and distinctive terms it mentions. Each changed file is in scope if the issue names it, its directory or its stem; if its changed code touches a name from the issue; if its path and changed names share enough issue terms; or if it is a companion of an in-scope file (its test, or a file that imports it). Every other part is flagged with a reason and a category: unrelated code, docs, tests, CI, dependencies, or formatting-only hunks. CI and dependency edits are always flagged unless the issue mentions them. If the issue names nothing concrete, Fence calls the PR \emph{scope unresolvable} and flags only CI, dependency and formatting parts; we exclude these \nUnres{} PRs (\pctUnres\%) from rates.

\textbf{Metrics.} A PR \emph{reaches} if Fence flags any part. \emph{Scope reach} is the share of changed lines in flagged parts. Rates have Wilson 95\% intervals, means have bootstrap intervals, and the overall rate also has a repository-clustered bootstrap interval.

\textbf{External labels and baselines.} PAIChecker~\cite{wang2026paichecker} released human labels for issue/patch pairs in SWE-bench~\cite{jimenez2024swebench}, SWE-Gym~\cite{pan2025swegym} and SWE-bench Multilingual; one label is scope creep. We score \nPai{} labelled instances (\nPaiSC{} scope creep) and compare Fence with four baselines: PR size in changed lines, file count, top-level directories and TF-IDF distance between issue and diff.

\subsection*{RQ3: What explains the differences?}
Mostly PR size. Bigger PRs give Fence more parts to flag, and its reach correlates with file count (Spearman $\rho=\rhoFiles$). Copilot's PRs have a median of \filesCopilot{} files against \filesClaude{} for Claude Code, and \bigCopilot\% change more than 16 files (Claude Code: \bigClaude\%). Re-weighting each agent to the corpus file-count mix shrinks the spread from \reachJules--\reachCopilot\% to \stdClaude--\stdCursor\% (Table~\ref{tab:agents}, Fig.~\ref{fig:bins}). Missing patches do not explain it (\missCopilot\% of Copilot file rows, \missAll\% overall). What remains is partly template files: Copilot PRs edit \texttt{README.md} (\readmeCopilot\% vs \readmeOther\% for other agents), \texttt{package.json} (\pkgCopilot\% vs \pkgOther\%) and its own \texttt{copilot-instructions.md} (\instrCopilot\% vs \instrOther\%) without being asked.

The same caution applies to outcomes. Merged PRs are flagged slightly more often than unmerged ones (\mergedReach\% vs \unmergedReach\%, \mergeRaw{} points), but at the same file-count mix the difference is \mergeStd{} points \ciMergeStd. We find no evidence that Fence's flags predict merging once size is held fixed.

\subsection*{RQ4: Do Fence's flags agree with human scope-creep labels?}
Not better than PR size (Table~\ref{tab:pai}, Fig.~\ref{fig:auroc}). On PAIChecker's labels, PR size reaches AUROC \aucSize{} \ciAucSize{} and Fence's reach \aucFence{} \ciAucFence. Flagging the same \paiBudget{} instances that Fence flags, PR size has \precSize\% precision and \recSize\% recall, Fence \precFence\% and \recFence\%. In 5-fold cross-validated logistic regression, adding Fence to size changes AUROC from \cvSize{} to \cvSizeFence{} (paired bootstrap gain \cvDelta{} \ciCvDelta), and within PR-size terciles Fence's AUROC is \tercSmall, \tercMid{} and \tercLarge. Two differences limit the comparison: the labels are per PR on human-written gold patches, not agent PRs, and PAIChecker's scope creep includes over-reach inside files the issue does name, which file-level rules cannot see. Still, Fence's flags cannot be read as a scope-creep score until its precision on agent PRs is measured.

\section{Threats to Validity}
\emph{Construct.} Every rate is Fence's output. Fence can be wrong in both directions: it flags support edits a reviewer would accept (an import, a test fixture), and it misses over-reach inside in-scope files. We drew a gold sheet of \goldPRs{} PRs (\goldPerAgent{} per agent, \goldFiles{} files) with a labeling app and a \emph{scope unresolvable} option, but no human has labelled it yet, so we report no precision, recall or agreement. Some extras are welcome: a maintainer may ask for them in comments rather than in the issue. \emph{Internal.} AIDev stores one patch per commit and file, so lines rewritten across commits can be counted twice. \emph{External.} Copilot PRs often lack patches and are under-represented, and the task-type subset is small.

\section{Related Work}
PR-MCI~\cite{gong2026prmci} measured disagreement between an agent PR's description and its code, not its issue. Işık et al.~\cite{isik2025forge} and Altunhan et al.~\cite{altunhan2026finetune} used LLMs to classify issue/PR pairs as exact, missing or tangled. PAIChecker~\cite{wang2026paichecker} found misaligned issue/patch pairs in SWE-bench-like benchmarks. Overeager agents~\cite{qu2026overeager}, SWE-Misbehavior~\cite{trong2026swemisbehavior} and Refactoring Runaway~\cite{tian2026runaway} study out-of-scope agent behaviour in controlled settings. Unlike these, we measure scope at the level of individual files and hunks, on real agent PRs, without an LLM.

\section{Conclusion}
By a deterministic checker's flags, more than half of agent PRs with a linked issue change something the issue does not point to, but agent differences mostly follow PR size, and on independent human labels PR size is the better signal. The next step is to label the gold sheet and report Fence's precision. Code, per-PR scores, the gold sheet and the labeling app are at \url{https://github.com/ReviewDebtZero/rd0-fence}.
